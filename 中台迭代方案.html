主要差距

  • 策略只沉淀、不生长：验收 KPI 未回流成策略节点效果权重。
  • 资产未分层：模板 / 知识 / 护栏仍是“按行业各存一份”，缺平台级共享资产 + 品牌级实例。
  • 无独立开发者后台：品牌管理、资产管理、计量对账、审计缺失。
  • 无品牌分支机制：不能快速派生、同步、升级、解约客户品牌。
  • 真实渠道与商业数据未接入：企微、容联云短信、巨量 / 小红书 / 抖音 / 蝉妈妈待联调。
  • 飞书未接入：群聊 / 客服动作 / 运营效果无法实时回流。
02

目标架构 · 自生长策略神经元

平台内核（神经元）策略引擎（节点 + 效果权重 + 场景关联）、行业策略库、平台知识库与护栏、模型网关、渠道适配器、计量计费、开发者后台、版本管理、飞书实时信号通道
品牌实例（分支）从平台内核（神经元）派生：行业 + 模板 + 品牌知识 + 违禁词 + 渠道 + 权限；策略/模板/知识默认平台级共享，品牌可私有覆盖；业务数据完全隔离；现有 Tenant 直接升级为分支实例

P1 平台内核与开发者后台

  • P1-1 策略引擎 v1（效果回流）：指令沉淀策略卡时建立关联；验收 KPI 回写 runs / wins / score；飞轮建议按效果分排序。
  • P1-2 平台级资产模型：行业模板、知识库、护栏升级为“平台默认资产 + 品牌覆盖实例”，覆盖互不污染。
  • P1-3 开发者管理后台：仅内部使用；品牌派生 / 启停 / 解约 / 版本、资产管理、计量对账、操作审计。
  • P1-4 飞书双向接入：读取群聊 / 客服消息 / 动作，并从系统向飞书发消息、执行指令；客服动作与运营效果转成效果事件，与验收 KPI 一起更新策略权重。

P2 品牌实例化与策略生长

  • 现有 Tenant 直接升级为品牌分支实例；一键派生新分支，分支跟随平台版本升级，解约只停分支。
  • 策略节点标注行业 / 场景 / 人群 / 渠道，按相似度跨行业复用；AI 自动组合已验证打法生成候选策略，人工审核通过后沉淀。
  • 效果图谱：策略节点 + 关联边（相似场景 / 上下游 / 替代关系）可视化。

P3 渠道与开放生态

  • 容联云短信真实发送；企业微信真实发送（会话存档可选）。
  • 商业数据源接入：巨量、小红书、抖音、蝉妈妈（按客户签约增购）。
  • 开放 API 与外部客服桥接：第三方平台可推送信号、创建指令、查询执行结果。

P4 规模化与商业化

  • 多租户隔离强化、数据权限、安全合规。
  • 按客户对账单与成本分摊（LLM / 短信 / 渠道）。
  • 平台级经营驾驶舱；监控、告警、备份、灾备、灰度发布。

05

技术要点 · 风险 · 节奏

技术实现要点
  • 平台级资产 / 策略节点模型；Tenant 直接升级为品牌分支实例；策略卡增加效果统计。
  • 资产规则：策略 / 模板 / 知识默认平台级共享，品牌私有覆盖；业务数据按品牌完全隔离。
  • 回流链路：验收 KPI + 飞书效果事件 → 策略节点权重 → 飞轮建议排序。
  • 新增开发者后台路由；运营工作台按品牌实例渲染。
  • 平台资产带版本，品牌实例记录应用版本；每切片补自动化测试。
依赖与风险
  • 渠道 / 数据源权限：巨量、小红书、抖音、蝉妈妈需服务商资质与报价。
  • 飞书权限：自建应用需开通群聊 / 消息 / 审批权限。
  • 模型成本随客户增长，靠预算上限 + 按客户计量控制。
  • 合规：品牌违禁词、行业监管、客户数据隐私；保持向后兼容。

执行节奏

  • 先做 P1-1 策略效果回流，让“神经元靠分支生长”闭环先跑起来。
  • 再做 P1-2 / P1-3 / P1-4，P1 完成后接 P2 品牌实例化，形成完整自生长策略神经元雏形。
  • P3 / P4 按渠道授权与商业化节奏推进。
